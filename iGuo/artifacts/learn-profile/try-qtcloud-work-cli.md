# 试用量潮工作云命令行工具

这是一份**学习任务书**：请你把量潮工作云命令行（`qtcloud-work`）用一遍，然后把遇到的问题交回来。

这一版是预发布（`0.1.0-alpha.4`），好用不好用我们自己也不知道。你的角色不是来学一个成熟工具，而是**来把它用坏**——挡住你的地方、看不懂的地方、缺的地方，都是我们要的答案。

## 它是什么

把知识工作做成可执行的编排：**工作流**定义干什么（一串步骤，每步写着谁做、怎么算完），**任务**记这一次怎么走（流水、闸门、产物落点），**判据**判算不算完。全程在本地文件里跑，不启服务、不连数据库。

## 第一步：装上

```bash
cargo install qtcloud-work-cli
qtcloud-work --version      # 应显示 0.1.0-alpha.4
qtcloud-work help           # 导览：有哪些命令
```

没装 Rust 就先装 rustup（`https://rustup.rs`）。装不上、报错，就是第一条发现，照下面第三题记下来。

## 第二题：跑通一遍（必做）

在一个**空目录**里照做——它只会往这个目录下的 `data/` 写东西，不会碰别处。

```bash
qtcloud-work help
qtcloud-work help workflow
qtcloud-work workflow --new 试一条 --steps 甲,乙
cat data/workflows/试一条.yaml          # 看看它写出来的骨架长什么样
qtcloud-work workflow 试一条 --check     # 核对这条定义
qtcloud-work task --new 试一条 --workflow 试一条
qtcloud-work task 试一条                 # 看步骤状态
qtcloud-work task 试一条 --done 甲 --note "我做的"
qtcloud-work task 试一条 --next          # 交给 AI 跑；没装 pi 会跑不动，用 --done 记
qtcloud-work catalog                     # 随便看看工作区
qtcloud-work find 试一条
```

把敲过的命令**按顺序**贴回来（这就是复现步骤）。

## 第三题：写一条真工作流（必做）

挑一件你**每周都要重复做、又烦**的事（整理课程作业、清理下载目录、给同学发通知、跑实验数据……），把它写成一条工作流：

- 两到五步，每步写清谁做（`executor: agent` 或 `human`）与怎么算完（`criteria`）；
- 至少一条 `rule` 判据：`path`（路径在）/ `absent`（路径不在）/ `file` + `contains`（文件含某段文字）/ `run`（命令退出码为零）任选；
- 留一条 `human` 判据当闸门（这一步要人点头才能往下走）；
- 用 `qtcloud-work workflow <名字> --check` 自检，改到它不报错为止。

交：那份 YAML（命名成 `学号-工作流名.yaml`），加一句话说它替你省掉了什么。

## 第四题：问题清单（本次重点）

分三类，按你遇到的顺序写，**一条也算，不必凑数**：

- **挡住我**：跑不通、报错、卡住——贴命令与报错原文；
- **看不懂**：帮助、文档或输出里说不清的地方——写下你当时以为它是什么意思、实际是什么；
- **缺**：你想做却做不了的——写下你想要什么、为什么想要。

每条尽量带齐四样：**环境**（系统、`--version`）、**命令**、**期望**、**实际**。

## 怎么算做得好

- 复现步骤让别人照着能重跑一遍；
- 问题的「命令—期望—实际」对得上，不夹评价、不夹赞美；
- 那条工作流你真的跑起来了（`--check` 不报错、`task` 能走）。

## 边界

- 预发布版，会用坏、会变；别在正式仓库里跑，只在自己的目录里试；
- **不用读源码**，也不用给修复方案——你是使用者，看到的就写下来；
- 没装 `pi` 的同学：第二题的 `--next` 会跑不动，用 `--done` 记一笔就行，这条卡点本身也算一条发现。

## 交到哪

把「问题清单」与那份 YAML 交到课程指定的位置（一个文件，或仓库里一个 issue）。命名：`学号-试用量潮工作云命令行.md`。
