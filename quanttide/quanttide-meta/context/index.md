# 元工程

宣传册和札记的主要区别是：宣传册会带有一种“我有一个好东西想跟人分享”的情绪，而札记带着一种冷静的思考，即“我们为什么这个能成”。

**实验室转平台**：刚把「实验室转平台」交给 AI 执行，这个工作比较吃工程标准，人在其中比较累。

**命令行汇总**：要求命令行工具把这些汇总起来，在流程里拼各种 AI 与人工，把工作做出来。

**左脚踩右脚**：用实验室与平台相互迭代，也就是「自举」；一个环节创造、一个环节整理，可能让两个平台迭代更快。

**积木堆叠与规则引擎**：积木堆叠对人类很难，对规则引擎就是填空；用 AI 写规则引擎，固定下来再执行，比较清楚。

**发布预检查**：自研的 code 命令与 devops 命令可以在发布时先做预检查，再发布。

**设计意图固定化**：设计意图中已有的想法会固定化，领域与其他领域的关系越来越清晰，知道如何加强其他领域建设，并把现成的工作流乃至样例提供下来。

**命令行可内测**：工作命令行发布之后，就可以开始内测了。

**洗上下文**：今天的主要工作是优化命令行表现，让它逐渐脱离生长的上下文也能正常使用；要不断把上下文洗干净。

**工程质量之问**：系统整合与迭代会空前加快；新的问题是怎么保证工程质量，工程就是编程，云在这一块的工作量不小，会是一个大坑。

**领域建模框架**：核心是对每个领域有一套建模框架，这个框架提供 harness 机制，其中有动态环节，让它具备元工作能力，可以生成很多很多东西。

**IaC 与 CI 的灵感**：IaC 的资源声明让人想到去声明产物，CI 让人想到流水线；这两个思想可以应用在几乎所有体系之中。

**本地版先行**：命令行客户端先做本地版本，把命令行工具封装起来作为早期替代；先把流程和能用的东西搞出来，再逐渐改变数据源的获取。
