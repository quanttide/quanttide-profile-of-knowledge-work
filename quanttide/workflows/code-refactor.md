# 代码重构

把一条工作流定义重构到四段精确——输入、过程、输出、验收，判准是每一句声明都能派生出判据。这里的「代码」指工作流定义本身：平台上真正被机器执行的就是它。

目标定义由起任务时指定，任务名与被重构的定义同名，即 `<工作流目录>/<任务名>.yaml`。产物分两份：给机器的修订稿，给给人的判断。

## 五步

1. read——读清楚目标定义。逐字段读，不猜；把每步 description 里的散文摘成输入、过程、输出、验收四类，写进报告附录的「现状」一节，每条注明出自哪一步的哪句原文。
2. gap——找缺口、下判断。先写一条主诊断说清这条工作流最缺什么，再列至多五条缺口（缺在哪句、什么后果、补齐后能派生哪条判据）；其余观察进「旁枝」。
3. precise——写修订稿。把缺口补成声明，修订后的完整定义落 `<数据仓>/artifacts/proposed/<任务名>.yaml`；具体值只在修订稿里出现一次，报告不复述。
4. migrate——列迁移建议。让修订稿生效要改哪些地方——定义、规格、实现 schema、用例测试、其余工作流，逐处写清改什么、为什么、破坏性还是可并存，按先后排序。
5. conclude——收口。报告「结论」一节写这份工作流是什么、最缺什么、先改哪一处，附改动前后的判据条数对照，末尾一句复述主诊断；最后请创始人拍板。

## 产物

修订稿落 `<数据仓>/artifacts/proposed/<任务名>.yaml`；报告落本任务的草稿区，含主诊断、建议、结论与现状、缺口、迁移三个附录，全篇不超过 80 行。

## 怎么跑

```bash
qtcloud-work task --new <目标名> --workflow code-refactor
```

再 `qtcloud-work task <目标名> --next`，一条一条走。
