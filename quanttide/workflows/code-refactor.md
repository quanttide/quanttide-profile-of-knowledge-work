# 代码重构

把一条工作流定义重构到四段精确——输入、过程、输出、验收，判准是每一句声明都能派生出判据。这里的「代码」指工作流定义本身：平台上真正被机器执行的就是它。

目标定义由起任务时指定，任务名与被重构的定义同名，即 `<工作流目录>/<任务名>.yaml`。产物分两份：给机器的修订稿，给给人的判断。

## 步骤与验收

### read 读清楚

逐字段读目标定义，不猜——顶层字段、每一步的 name / executor / criteria；再把每步 description 里的散文逐条摘出来，分成输入、过程、输出、验收四类。摘出的每条写进报告附录的「现状」一节，注明出自哪一步的哪句原文。

验收：程序查报告附录里有「## 现状」一节；智能体审逐字段读出、没漏没补，且每条都注明出自哪一步的哪句原文。

### gap 找缺口

按四段逐段比，只挑最要紧的：一条主诊断（这条工作流现在最缺什么，一句话）加至多五条缺口（缺在哪句、什么后果、补齐后能派生哪条判据），写进报告的「主诊断」与附录「缺口」；其余观察进附录「旁枝」。

验收：程序查报告里有「## 主诊断」「## 缺口」，且主诊断排在附录之前；智能体审主诊断一句话说得出最缺什么，缺口不超过五条、超出的进了旁枝。

### precise 写修订稿

把缺口补成声明：输入（读什么、不许读什么）、过程（工具白名单、必做子动作与中间产物、禁忌）、输出（落点、形态、上限、必带字段）、验收（能派生的交给派生，剩下写明判准）。修订后的完整定义落 `<数据仓>/artifacts/proposed/<任务名>.yaml`；具体值只在那一份里出现一次，报告另写「建议」一节，只说改了哪几处、每处派生出哪条判据。

验收：程序查修订稿落在 proposed 目录、报告里有「## 建议」；智能体审修订稿与目标定义同构（顶层与步骤字段读得进）、四段齐全、每条声明可派生，且具体值只在修订稿里出现一次、报告不复述。

### migrate 列迁移建议

列出让修订稿真的生效要改哪些地方——定义本身、规格、实现 schema 与派生、用例测试、其余在用的工作流；逐处写清改什么、为什么、破坏性还是可并存，并按先后排序。写进报告附录的「迁移」一节。

验收：程序查报告附录里有「## 迁移」一节；智能体审清单覆盖定义、规格、实现、测试、其余工作流五处，标出破坏性与可并存，并按先后排了序。

### conclude 收口

写报告的「结论」一节：开头三行依次是这份工作流是什么、最缺什么、先改哪一处，随后给改动前后的判据条数对照，末尾一句复述主诊断。

验收：程序查报告里有「## 结论」、结论排在建议之后、全篇不超过 80 行；智能体审结论开头三行齐全、给了改动前后的判据条数对照，且「主诊断＋建议＋结论」单独拿出来能当一份能直接用的判断；人拍哪些先改、哪些先不动。

## 产物

修订稿落 `<数据仓>/artifacts/proposed/<任务名>.yaml`；报告落本任务的草稿区，含主诊断、建议、结论与现状、缺口、迁移三个附录，全篇不超过 80 行。

## 怎么跑

```bash
qtcloud-work task --new <目标名> --workflow code-refactor
```

再 `qtcloud-work task <目标名> --next`，一条一条走。
