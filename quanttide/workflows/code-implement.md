## 路线

实验室（`examples/default/`，Python 写的 kg 原型）已经配了初步文档，结构与平台的基本一致，但这段维护过程很乱。往上走的路子是把这套做法扶正：**先重写一份文档，再照文档里的用例设计测试、验证测试真的在验业务，最后才写实现代码**。文档驱动加测试驱动，终点是平台上真能用的能力。

目标仓是 `apps/qtcloud-work/src/cli`：Rust + clap，命令行这条骨架的形状与实验室的框架一致（子命令、JSON 输出、版本与变更脚本都在），实现语言与实验室不同（Python 对 Rust）。这一轮**不对接 provider**，先在本地把这套做法做出来。

## 步骤与验收

### outline 列清单

逐动作、逐字段、逐判据列出这份规格要写什么。来源是实验室已经实现的东西，双向对账：实验室有的不能漏，清单里也不能凭空多出没做过的事。清单写进本任务的报告。

验收：程序查报告里有「## 清单」一节；智能体审清单每条都有出处（实验室的实现或规格），没有凭空造出来的条目。

### doc 重写文档

照清单重写三部分：`user-guide`（怎么用）、`dev-guide`（程序怎么继续长）、`api-references`（命令与数据的参考）。实验室那份不搬。真实业务写成用例，沉在 `user-guide` 里——做过几件写几件，没做过的不写。

验收：程序查 `apps/qtcloud-work/src/cli/docs/` 下 `user-guide/index.md`、`dev-guide/index.md`、`api-references/index.md` 三份都在，且 `user-guide` 里有「## 用例」；智能体审清单里的条目都落到了文档里、用例都出自做过的真事；人拍文档定稿（内容取舍只能人拍）。

### test 照用例设计测试

一条用例一组测试，测试写在 `apps/qtcloud-work/src/cli/tests/usecases.rs`，每条测试上面一行注释写出处（形如 `// 用例：一`）；写 `apps/qtcloud-work/src/cli/scripts/validate-usecases.sh` 做双向对账——文档里的用例号与测试里的出处，两边集合必须相等。对账结果与一次红的记录写进报告的「对账」一节。

验收：程序查测试文件与对账脚本都在、对账跑得过（两边名字相等）、实现缺席时测试是红的、报告里有「## 对账」；智能体审每条用例都有测试，没有恒绿的空壳。

### code 开发代码

实现让测试变绿，逐条转绿的过程记进报告。这一轮先不接 provider，本地做法照实验室的来。文档与测试这一轮不动，要改从文档改起。

验收：程序查测试不是零条（空壳挡在这里）、测试全绿；人拍代码验收（能不能上平台）。

## 固定的形状

对账要能机械地判，形状就得定死。

**文档**分三份，都在 `apps/qtcloud-work/src/cli/docs/` 下；用例写在 `user-guide/index.md` 里，每条一个小节，标题形如 `## 用例 一、起一件任务并走一步`。

**测试**写在 `apps/qtcloud-work/src/cli/tests/usecases.rs`，每条测试函数上面一行注释写出处，形如 `// 用例：一`。

**对账**由 `apps/qtcloud-work/src/cli/scripts/validate-usecases.sh` 承担：抓文档里的用例号与测试里的出处，两边集合必须相等，不等就报错退出。

## 已定

- **文档正本**：重写一份，不搬运实验室那份；正本落在 `apps/qtcloud-work/src/cli/` 自己的文档里——它是平台侧能力的规格，跟着被实现的那一侧走；
- **平台侧这一轮**：先不接 provider，本地这条做法照实验室的来，接口层等 provider 就位后另起一轮；
- **测试的出处**：文档里的用例，以文档为准；
- **用例范围**：不是选题——真实发生过的都写（做过几件写几件），没做过的不写；
- **文档三部分**：`user-guide`、`dev-guide`、`api-references`（英文名定路径）。

## 产物

每一步都有自己的产物：清单（进报告）、三份文档（含用例）、对账脚本与一次红的记录（进报告）、实现代码与绿的结果。文档与测试落在平台仓 `apps/qtcloud-work/src/cli/`，本任务的报告与流水落草稿区 `data/context/qtcloud-work/`。

## 还会粗糙的地方

判据目前只核到「文件在不在、脚本过不过」这一层：清单是否逐条有出处、文档是否把清单写全、每条测试是否真在验业务，仍要智能体读一遍再判。要让机器多担一点，办法是把形状再定死一些（例如清单条目也编号、测试用例与清单条目对起来），代价是文档写起来更板。
