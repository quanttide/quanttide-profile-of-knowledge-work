# studio 代码实现

（草案，边讨论边细化，定了再落成定义）

## 路线

studio（`apps/qtcloud-work/src/studio`，Flutter 客户端）现在是个窗口：起子进程调 `qtcloud-work`，读它给回来的统一信封。这一轮变的就是这一层——**同一套行为用 Dart 再实现一遍**，studio 不依赖命令行也能把活干完。

搬的是行为，不是壳。命令行那边一个模块一个模块读透（字段怎么校验、报错怎么说、边界怎么算），在 `lib/core/` 里照着实现，测试逐条照着它的规矩写。

## 尺子

`apps/qtcloud-work/src/studio/scripts/parity.sh`：同一处工作区、同一条命令，命令行与 studio 各跑一次，比输出信封（`ok` / `columns` / `rows` / `lines`）。结论只有三种——**一致 / 不一致 / 没搬**，后两种都算不过。

为什么比信封：它是两侧唯一的公共面。`ok` 定退出码，`lines` 给人看，`columns` 与 `rows` 给窗口画。比它，等于比「同一件事算出来的结果」，不掺界面与语言的差别。

## 步骤与验收

### census 点货

把命令面（`qtcloud-work help` 那一页）逐条列出，每条标出 studio 侧的对应物与状态：已搬 / 没搬 / 搬得不一致。再跑一遍尺子，当前的红绿原样记进报告的「点货」一节。

验收：程序查尺子跑得起来（红绿都算数，但不能跑不起来）、报告里有「## 点货」；智能体审清单覆盖命令面每一条、没有「（待查）」；人拍先搬哪些。

### port 搬一个模块

一次只搬一个模块。先读透它的行为与**报错文字**，再用 Dart 实现，照它的规矩写同义测试。

验收：程序查 `flutter analyze` 与 `flutter test`、报告里有「## 搬运」；智能体审边界（缺字段、多字段、取值不对各报什么）与报错文字逐条对上、测试与命令行同义，不是自说自话。

### parity 对表

跑全量对表，把「不一致」查清是行为差异还是序列化差异（键序、空数组、路径写法），改到一致。改的是 studio，不是尺子。

验收：程序查尺子全绿、报告里有「## 对表」；智能体审每条不一致都查清了来路。

### handover 交接

撤掉 studio 里起子进程那层，界面每一处显示改成走自己的实现；doc 里那些「命令行还没给」一并撤。

验收：程序查 `lib/` 里没有 `Process.run`、没有占位说明、门禁全绿、报告里有「## 交接」；智能体审界面每处数据都能指到自己的实现；人拍可以不再依赖命令行。

### conclude 收口

三行（搬完了什么 / 能不能自己干完 / 还差什么）+ 拿不准的。

验收：程序查报告里有「## 结论」；智能体审三行说得清、拿不准的单列。

## 固定的形状

**信封**是两侧的接口：`{ok, lines, columns, rows}`，字段名与含义都不改。

**报错文字**沿用命令行那一份，逐字不动——同一件事在两边给人看的话要一样。

**尺子**只认三种结论；不一致与没搬都让这一步红。

**一次一个模块**：搬完一个，尺子绿一片，再上下一个。

## 已定

- **命令行与 studio 都留着**：命令行是平台本体（其他仓、CI、发布流程都挂在它上面），studio 是客户端的自己干活，两边都要能单独把一套活干完；
- **防漂**：同一套用例、同一把尺子。哪边改了行为，另边红；红的那边说明白，不许两边各说各话；
- **命名**：步骤名与 `code-implement` 一个体例（点货、搬运、对表、交接、收口），因为干的是一件事——照规格把代码写出来；
- **尺子随搬运扩大**：命令面搬完一条，`parity.sh` 的默认清单就多一条。

## 产物

一个 Dart 模块加一组测试（落 `apps/qtcloud-work/src/studio/`），点货与对表的输出（进本任务的报告）。报告与流水落草稿区 `data/context/qtcloud-work/`。

## 还会粗糙的地方

判据目前只核到「门禁绿加尺子绿」：报错文字是否逐字对上、测试是否真在验行为，仍要智能体读一遍再判。尺子比的是信封，界面上的差别（布局、交互）它一概不管，那部分只能人看。
