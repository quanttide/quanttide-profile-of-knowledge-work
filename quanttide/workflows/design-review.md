# 设计评审

评审一张界面截图。人先给一句第一眼，智能体再清点、给主诊断与证据、按影响提建议，最后复述一句请人拍板。报告按倒金字塔排。

## 步骤与验收

### impression 第一眼

由人写：一句话说这张图给人的整体感受（判断，不是清点），写进报告的「第一眼」一节。

验收：程序查报告里有「## 第一眼」；智能体审那一句是判断，不是清点（一句话读得出整体感受）。

### look 清点

把图上真有的东西看清楚：有哪些对象、状态、动作、数字，逐区写进报告的「看到」一节。这一节只清点、不下判断。

验收：程序查报告里有「## 看到」；智能体审这一节里全是清点，没有「混乱」「不合理」这类判断词，也没有编造。

### review 判断与证据

先在报告的「主诊断」一节写一句话说清这张图最主要的问题，与人的第一眼对照——一致就说明理由，不一致就说明为什么；再在「证据」一节列支撑它的观察，至多五处，每处点到图上具体位置；其余观察放进「旁枝」一节当附录；截图上读不出、需要人确认的放进「拿不准」一节。

验收：程序查报告里有「## 主诊断」「## 证据」「## 旁枝」，且排在最前的三节顺序对（第一眼 → 看到 → 主诊断）；智能体审主诊断一句话说得清、与证据对得上，证据不超过五处且都点到图上位置，判断与拿不准的事分开写。

### advise 建议

写进报告的「建议」一节：按影响从大到小排，每条写清改哪里、改成什么、为什么，并标出影响面（安全 / 效率 / 辨识）与改动代价（小 / 中 / 大）。

验收：程序查报告里有「## 建议」；智能体审每条建议都带影响面与改动代价，且按影响排序。

### conclude 收口

报告的「结论」一节：开头三行依次写「是什么」「问题在哪」「先改什么」，随后一句话复述这张图的问题并与「第一眼」对照，再列仍拿不准的地方。

验收：程序查报告里有「## 结论」且排在建议之后；智能体审结论开头三行依次是什么、问题在哪、先改什么，且一句话复述与第一眼对得上；人拍哪些建议采纳。

## 产物

本任务的报告，排成「第一眼 → 看到 → 主诊断 → 证据 → 旁枝 → 建议 → 结论」。

## 怎么跑

```bash
qtcloud-work task --new <任务名> --workflow design-review
```
